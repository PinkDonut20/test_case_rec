# Test task baseline: Document preprocessing + OCR + field extraction

Сделал быстрый Google Colab ноутбук без токенов и внешних API:

- `colab_document_ocr_pipeline.ipynb`

## Что реализовано

1. Выравнивание документа на фото (OpenCV, поиск 4-угольного контура + perspective transform).
2. OCR текста (EasyOCR, локально, CPU/GPU).
3. Извлечение структурированных полей с приоритетом русского текста:
   - `full_name`
   - `birth_date`
   - `document_number`
4. Сохранение результатов:
   - выровненное изображение
   - изображение с детекциями/текстом
   - JSON с полями и полным OCR

## Важные улучшения под русский язык

- Улучшен выбор ФИО: учитываются соседние строки и отсекаются географические/служебные фразы (`ОБЛ`, `МОСКВА`, `РЕСПУБЛИКА` и т.д.).
- Подписи на изображении рисуются через PIL + DejaVuSans, поэтому русский текст не превращается в `????`.
- В JSON сохраняются и `text_raw`, и `text_normalized` (нормализованный русский текст).
- Добавлена нормализация смешанной латиницы/кириллицы (типичная OCR-ошибка для русских документов).
- Добавлен второй JSON-файл в кодировке `utf-8-sig` для более корректного открытия в некоторых редакторах Windows.

## LLM-режим (опционально)

В ноутбуке есть гибридный extractor:
- база: эвристики (быстро и стабильно)
- опция: локальная LLM через `transformers` для доизвлечения полей

Переключатели через переменные окружения:
- `USE_LLM_EXTRACTOR=1` — включить LLM-извлечение
- `DOC_LLM_MODEL=TinyLlama/TinyLlama-1.1B-Chat-v1.0` — модель (можно заменить)

По умолчанию LLM выключена, чтобы быстро запускалось.

## Тесты в Colab

Добавлена ячейка smoke tests:
- проверяет, что ФИО не подхватывается из строки региона
- проверяет извлечение даты/номера
- проверяет JSON-сериализацию результата

Эту ячейку лучше запускать до реального документа.

## Как запустить

1. Открой `colab_document_ocr_pipeline.ipynb` в Google Colab.
2. Запусти ячейки сверху вниз.
3. (Опционально) включи LLM через `os.environ` в отдельной ячейке до инициализации extract-функций.
4. В ячейке `files.upload()` загрузи фото документа.
5. Получишь:
   - визуализацию в ноутбуке
   - файлы в папке `outputs/`

## Почему это подходит под тестовое + интеграция в Docker

- Python + локальный инференс (без ключей и токенов).
- Работает на CPU и на GPU (`torch.cuda.is_available()`).
- Есть полный рабочий pipeline от входного изображения до структурированного JSON.
- Поведение LLM/без LLM задаётся env-переменными — это удобно для `docker-compose` (те же переменные перенести в сервис).
